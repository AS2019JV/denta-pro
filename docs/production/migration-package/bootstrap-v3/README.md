## Fallo entre fases: estado terminal explícito

Los commits baseline/seed/upgrade/open son fases separadas; no se presentan como una única transacción. Tras cualquier fallo o resultado incierto, suspender el ensayo y sus clientes, conservar recibos y ejecutar únicamente el `90-quarantine.sql` aprobado y guardado al destino exacto para cerrar USAGE public a PUBLIC/anon/authenticated/service_role. Antes de abrir ya está cerrado; después de abrir esta fase vuelve a cerrarlo. Verificar denegación efectiva; si la cuarentena falla, mantener los clientes detenidos y escalar el diagnóstico sin conceder permisos ni cambiar configuración no aprobada. No auto-reinstalar, reparar historial, borrar datos o reintentar una fase comprometida. Queda un destino sintético parcial **cerrado**, no aceptado y no reentrante. Continuación requiere estado exacto reconciliado y propuesta/aprobación nueva, o un destino nuevo autorizado; no se infiere de esta aprobación. No recuperar sobre el origen.
